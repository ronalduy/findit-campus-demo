FINDIT CAMPUS LIVE XAMPP TEST CHECKLIST
======================================
Record a test as passed only after doing it on the target devices.

INSTALL / DATABASE
[ ] Apache starts in XAMPP
[ ] MySQL starts in XAMPP
[ ] SQL imports without errors
[ ] Admin can sign in with admin / 1234 on first setup
[ ] Admin password is changed before public/real use
[ ] Connection test page shows a valid database connection

PHONE / LAPTOP SHARED CONNECTION
[ ] Phone and laptop are on the same Wi-Fi
[ ] Laptop opens the app with localhost
[ ] Phone opens connection-test.php using the laptop IPv4 address
[ ] Phone submits the temporary code
[ ] Laptop shows Phone connected within a few seconds
[ ] Student application submitted on phone appears in Admin queue within about 5 seconds
[ ] Admin approval on laptop changes account status on phone after refresh/re-check
[ ] Newly posted item on laptop appears on phone when its list is refreshed
[ ] The camera is tested separately over HTTPS on the phone (plain LAN HTTP may block it)

AUTHENTICATION / REGISTRATION
[ ] Invalid login gives a safe message
[ ] Three failed logins trigger a one-minute lockout
[ ] Registration requires ID photo, live selfie, details, password, privacy acknowledgement
[ ] Camera permission denied shows a useful error
[ ] Saved ID review image matches the landscape viewfinder crop
[ ] Saved selfie remains upright and matches the portrait crop
[ ] OCR results are editable; unclear text can be entered manually
[ ] Duplicate active Student ID is rejected
[ ] New student registration is Pending until reviewed
[ ] Pending student cannot log in
[ ] Admin can approve, reject, or request correction
[ ] Request Correction preserves the application/password/Student ID and allows resubmission
[ ] Reject removes active application so the same ID can be used for a new registration; rejected entry stays in Recycle Bin until expiry
[ ] Student can change password and delete their own account after confirmation
[ ] Admin can change username and password
[ ] Admin can delete student accounts to Recycle Bin

ITEMS / HANDOVER / RECYCLE BIN
[ ] Admin creates Lost report and Found item with unique reference number
[ ] Admin can change Lost item status (Open/Matched/Closed)
[ ] Admin can change Found item status (Available/Claim Under Review)
[ ] A Lost item cannot be handed over as a Found item
[ ] Handover form validates claimant name and captures Student ID if applicable
[ ] Successful handover marks the Found item Returned and hides it from available Found list
[ ] Delete handover history moves the handover row to Recycle Bin; item remains Returned
[ ] Delete item moves the item and dependent handover history to Recycle Bin
[ ] Recycle Bin has separate Deleted Items/Handovers and Deleted Accounts tabs
[ ] Item/account can be restored when IDs and references are not already in use
[ ] Recycle Bin records older than 30 days are purged during an Admin page visit
[ ] Activity log records administrative actions
[ ] CSV report export opens correctly in spreadsheet software
[ ] Private ID/selfie media is unavailable to unrelated students

LIMITATIONS TO UNDERSTAND
[ ] Admin auto-refresh runs every 5 seconds; it is polling, not WebSocket push
[ ] Browser camera usually needs HTTPS on a phone when using a LAN IP
[ ] This is a project prototype; complete school privacy/security review before real deployment
